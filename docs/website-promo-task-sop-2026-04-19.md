# RandomPokemon 推广任务说明与执行 SOP

## 1. 文档定位

本文档用于统一说明 RandomPokemon 推广提交流程的任务范围、执行标准、操作步骤、记录要求与质量检查要求。

适用场景：

- 导航目录站提交
- 工具收录站提交
- 与本轮任务直接相关的账号登录、表单填写、邮件验证、审核跟进与结果记录

本文档的目标是确保执行过程具备以下特征：

- 范围明确
- 标准一致
- 过程可复用
- 结果可复查

文档结构按“任务范围 -> 完成定义 -> 执行流程 -> 记录规范 -> 质量检查”组织，执行时应按章节顺序理解与落实。

本文档解决四类问题：

- 这次任务到底要做什么
- 哪些站点必须提，哪些可以跳过
- 每个站点应该怎么提、提完后怎么判断是否完成
- 后续复查时，去哪里看结果

## 2. 任务背景与范围

### 2.1 本轮主任务

本轮的强制范围是：

- 飞书营销文档中 `导航目录类提交` 目录下的全部导航站

执行要求：

- 该目录下的站点要从头到尾完整处理
- 不能只处理一段连续清单就视为完成
- 不能只记录已经做过的少量站点
- 执行过程中必须始终清楚：
  - 该目录总共有多少目标
  - 当前已经处理到哪里
  - 还剩多少未处理

### 2.2 本轮不纳入完成统计的内容

以下内容不属于本轮核心范围，除非任务另行要求，不应与导航目录类提交流程混在一起：

- 博客评论外链
- 论坛发帖
- 社媒发帖
- 中文社区投稿
- 其它非导航目录站点

这些内容可以单独形成后续任务，但不能掺入本轮“导航目录类提交”的完成统计。

## 3. 任务目标与完成定义

### 3.1 核心目标

通过向导航目录站提交 RandomPokemon，获取可索引的产品页、审核中的提交记录、或可复查的提交入口，从而为后续 SEO 外链建设提供基础资产。

### 3.2 任务完成的标准

只有同时满足以下条件，才算本轮任务完成：

- `导航目录类提交` 目录下的目标已全部逐一处理
- 每个目标都有明确结果状态
- 每个已提交目标都记录了后续复查入口
- 每个失败或跳过目标都记录了原因和对应页面
- 过程记录文档可支持后续人工复查
- 飞书营销文档中 `导航目录类提交` 章节已同步更新为本轮最终结果状态

### 3.3 不算完成的情况

以下情况都不算任务完成：

- 只处理了目录中的一部分站点
- 没有核对总数和断点
- 只知道“提过了”，但没有可复查链接
- 对 `待审核` 目标没有重新处理
- 跳过了大量站点但没有写明原因

## 4. 执行原则

### 4.1 结果优先

优先追求“站点有结果可复查”，而不是追求形式上的“我点过提交按钮”。

### 4.2 复查优先

每个站点的记录重点不是过程细节，而是：

- 后续去哪里看
- 现在是什么状态
- 是否已经出现产品页

### 4.3 信息完整度优先

在不编造信息、不违背事实的前提下，提交时应尽量把可填写字段补充完整，并尽量上传可用的图片、Logo、截图、视频等素材。

这样做的目的包括：

- 提高站点审核与收录通过率
- 提高产品页展示质量
- 提高用户点击与浏览意愿

执行时应遵循以下倾向：

- 能填的有效字段尽量填
- 能上传的有效素材尽量传
- 能完善的分类、标签、功能说明、社媒链接、使用场景尽量完善
- 如站点允许填写较长描述、富文本介绍、功能说明、应用场景、FAQ 等内容，默认采用“详细描述优先”策略，而不是只提交最短可过审版本
- 描述类字段的目标不是“把表单交上去”，而是“让审核者和用户快速理解产品是什么、有什么特点、适合谁、能解决什么问题”

### 4.4 真实状态优先

对站点状态的判断必须基于页面事实，而不是基于猜测。

例如：

- 出现公开产品页，且页面有产品信息，可判为 `已提交`
- 只有成功提示、后台页、审核页，没有公开页，应判为 `已提交，待审核`
- 页面直接要求付费、强制互链、登录失效、站点坏掉，应据实记录

### 4.5 不做虚假承诺

涉及合规、隐私、教育合规、未成年人、认证、企业资质等字段时，不能为通过表单而编造事实。

可采取的安全策略：

- 填真实信息
- 选保守选项
- 若站点必须要求无法确认的承诺，记录风险或失败原因

## 6. 结果状态体系

每个目标最终只能归入以下结果之一：

- `已提交`
- `已提交，待审核`
- `跳过：必须付费`
- `跳过：强制互链`
- `跳过：站点不适配当前任务`
- `失败：无法登录`
- `失败：无法提交`
- `失败：站点异常`
- `失败：邮件验证未完成`
- `失败：验证/验证码阻塞`

说明：

- `已提交`：通常指已经产生可访问的公开产品页，或站点明确显示已创建成功；如已确认公开页稳定可见，可在备注中补充说明
- `已提交，待审核`：提交已完成，但是否公开仍取决于审核

## 7. 判定规则

### 7.1 文档原备注如何解释

历史文档中的备注，统一按以下规则理解：

- 明确写 `已提交`、`已发`、`已发布`：视为已完成，不重复提交
- 只写 `待审核`：不算完成，本轮重新处理
- 写 `已提交，待审核`：说明此前已提交过，本轮默认不重复，除非任务明确要求重跑
- 没备注：本轮处理

### 7.2 本轮目录执行规则

对于本轮主任务目录，本轮执行时必须：

- 先拉平目录内所有目标
- 统计总数
- 标出起始点、当前断点、未处理数量
- 处理完成后再核对一遍，确保没有漏项

这是强制动作，不能省略。

## 8. 总体执行流程

整个任务按以下顺序执行：

1. 先通过 Feishu MCP 读取产品基本信息与营销素材，确认本轮提交所需的基础字段、介绍文案与展示素材
2. 读取 `导航目录类提交` 全量清单，并形成唯一基准清单
3. 做清单映射，明确总数、状态、断点
4. 以单站点为单位执行提交或判定跳过
5. 每完成一个站点，立即记录结果、复查入口与异常说明
6. 处理该站点提交后的邮件验证与确认动作
7. 在长时间执行过程中，必要时回看任务说明、当前进度和产品材料，防止执行偏移
8. 全部站点处理完后做尾部核对，确认无漏项
9. 将本轮最终执行结果回写到飞书营销文档的 `导航目录类提交` 章节，并完成一致性复核

## 9. 详细 SOP

### 9.1 阶段一：任务启动与清单准备

执行前必须先完成以下动作：

- 通过 Feishu MCP 读取飞书营销文档
- 定位到 `导航目录类提交` 目录
- 提取该目录下全部站点
- 形成执行清单

执行清单至少要包含：

- 序号
- 站点名
- 站点 URL
- 文档原备注
- 是否已完成
- 本轮处理状态

本阶段必须输出三个数字：

- 总目标数
- 已完成数
- 待处理数

如果这三个数字没有明确，就不能进入批量提交阶段。

此外，本阶段还必须明确本轮执行单位：

- 执行单位固定为“单个站点”
- 后续所有记录、校验、邮件处理都围绕单站点闭环展开
- 不允许先堆积一批站点不记录，再回头集中补记

### 9.2 阶段二：单站点预检查

处理每个站点前，先快速判断以下内容：

- 站点能否正常打开
- 是否确实是导航目录/产品收录站
- 是否存在真实提交入口
- 是否需要登录
- 是否明显必须付费
- 是否明显强制互链

如果在这一步已经确定无法继续，应立即记录并进入下一个站点。

### 9.3 阶段三：找到真实提交入口

优先寻找以下入口：

- `submit`
- `add tool`
- `submit project`
- `launch`
- `create listing`
- `list your tool`

要求：

- 必须进入真实表单或真实提交流程
- 不要把营销页、赞助页、价格页误当作提交成功
- 如果入口点进去只有付费方案，要记录为 `跳过：必须付费`

### 9.4 阶段四：登录与账号处理

登录优先级如下：

1. 复用浏览器现有登录态
2. 使用 Google 登录
3. 通过 `feishu-sheets-toolkit` 或等价飞书表格能力查询飞书账号表
4. 站内注册

处理规则：

- 能用 Google 登录就优先用 `zhugetd@gmail.com`
- 若需站内账号密码，必须先通过飞书表格能力查飞书账号表，不要靠浏览器手动翻飞书表格
- 若能注册且流程合理，可以注册
- 若登录系统损坏、社交登录失效、无账号且无法安全注册，记为 `失败：无法登录`

### 9.5 阶段五：填写表单

表单填写前，先读取飞书营销文档中从 `主要功能` 到 `Use Cases` 之间的内容，作为本轮提交的产品信息与营销素材基础。

表单填写时，优先保证以下字段正确：

- 产品名称
- 官网
- 邮箱
- 公司名
- 创建人
- Logo
- 截图
- 预览图 / 封面图
- 视频
- 短描述
- 长描述
- 分类
- 标签

填写原则：

- 优先使用飞书营销文档中上述区间的现成素材
- 长短描述按站点字段长度裁剪，但默认遵循“长描述优先、信息完整优先”，而不是“最短可提交优先”
- 分类和标签尽量贴近 AI video、AI image、text-to-video、image-to-video、text-to-image、image-to-image
- 如字段非必填，不为凑表单而硬填无效内容
- 如同一站点需要多个层次的介绍文案，优先按“短介绍 -> 长介绍 -> Product overview -> Key Features -> FAQ / Use Cases”的顺序选取与重组
- 如字段虽然非必填，但明显有助于收录、审核、展示或点击，应尽量补充，例如：
  - Logo、截图、封面图、预览图、宣传视频
  - 社媒链接、公司信息、价格模式、适用场景
  - 功能列表、亮点描述、标签与分类
- 如果站点支持上传多张图片、多段媒体或更丰富的展示内容，应尽量补齐到合理完整度，而不是只做最小化提交
- 如字段容量允许，应尽量覆盖产品概述、核心功能、主要特点、典型场景、目标用户和差异化价值，而不是只写一句口号式简介
- 如站点公开产品页会直接展示描述内容，提交后应检查页面上的文案是否足以让首次访问用户快速理解 RandomPokemon；若描述明显过短且站点支持编辑，应记为后续优化项

### 9.6 阶段六：提交后即时判断

点击提交后，必须立刻判断结果属于哪类：

- 失败原因

- 收到没收到

- 更新当前进度状态，例如已处理数、剩余数、当前断点
- 若该站点在当前轮次内已经形成稳定最终结论，可同步更新飞书营销文档对应站点的结果状态；如仍存在邮件验证、待审核或二次确认等未闭环事项，则先更新过程记录，待本轮整批收尾时统一回写飞书主文档
- 如该站点暴露出新的字段需求或素材需求，必要时回看任务说明和飞书材料，确认后再继续

单站收尾完成后，才能进入下一个站点。

### 9.9 阶段九：整批收尾

一轮跑完后，必须再次核对：

- 是否覆盖了 `导航目录类提交` 全部站点
- 是否存在未写结果的站点
- 是否存在只写“已处理”但没有链接的站点
- 是否存在 `待审核` 却没有可回查页面的站点
- 是否已将本轮最终状态回写到飞书营销文档 `导航目录类提交` 章节
- 过程记录文档、飞书营销文档与当前执行断点是否一致

只有整批核对通过，才能宣布本轮完成。

## 10. 跳过与失败处理规则

### 10.1 必须付费

如果站点只有付费提交，不提供免费或可接受的基础提交通道：

- 直接记为 `跳过：必须付费`
- 记录价格页或提交页链接
- 简述价格和阻塞点

### 10.2 强制互链

如果免费提交必须先在官网添加对方 badge、backlink 或站点链接：

- 直接记为 `跳过：强制互链`
- 记录要求页面
- 简述要求内容

### 10.3 站点不适配当前任务

如站点属于以下情况，直接跳过：

- 不是导航目录站
- 不是产品收录站
- 是纯资讯站、画廊站、工具站、卖货站
- 与 RandomPokemon 提交场景不匹配

结果记为 `跳过：站点不适配当前任务`。

### 10.4 无法登录

如遇以下情况：

- 登录页脚本损坏
- 社交登录不可用
- 注册流程不可达
- 账号体系无法取得

结果记为 `失败：无法登录`。

### 10.5 验证码或验证阻塞

如遇以下情况：

- 图片验证码无法识别
- Cloudflare/Turnstile 无法通过
- 验证邮件收不到
- 重发链接失效

根据情况记为：

- `失败：验证/验证码阻塞`
- `失败：邮件验证未完成`

### 10.6 站点异常

如遇以下情况：

- 500 报错
- 域名过期
- 提交页连接拒绝
- 证书错误
- 页面维护中

结果记为 `失败：站点异常`。

## 11. 过程记录规范

本任务必须同步维护单独的过程记录文档。

记录原则：

- 少写空话
- 只写后续复查有用的信息
- 一眼能看出去哪看结果
- 以单站点为单位实时记录
- 不采用“先跑一批，再集中补记录”的方式
- 过程记录文档负责保留操作细节、复查入口、邮件验证结果等过程信息；飞书营销文档负责保留可直接阅读的最终结果状态
- 两类文档必须保持一致，不能只更新过程记录而不回写飞书营销文档

每个目标至少记录：

- 目标名称
- 目标网址
- 文档原备注
- 本轮结果状态
- 产品页链接
- 审核页 / 后台页 / 临时查看页链接
- 邮件验证结果
- 页面是否有 RandomPokemon 信息
- 页面是否有官网链接
- 失败或跳过原因

记录时机要求：

- 每完成一个站点后立即记录
- 如站点还存在邮件验证、二次确认、审核跟进动作，也应先记录当前阶段状态，再继续后续动作
- 长时间任务执行过程中，如出现上下文变长、站点类型切换、字段要求变化等情况，应回看本文档、当前进度记录和飞书材料，再继续执行
- 本轮结束时，必须统一将最终结果回写到飞书营销文档 `导航目录类提交` 章节，并复核其与过程记录文档一致

## 12. 质量检查清单

每次执行完一批站点后，必须过一遍以下清单：

- 是否明确了本轮总目标数
- 是否记录了当前断点
- 是否把目录外目标混入了本轮完成统计
- 是否每个目标都有结果状态
- 是否每个已提交目标都有复查入口
- 是否在可行范围内尽量补充了完整字段与展示素材，而不是只满足最低提交要求
- 是否把 `待审核` 误当成已完成
- 是否把纯成功提示误当成公开产品页
- 是否把价格页误当成提交页
- 是否遗漏了邮件验证动作
- 是否已把本轮最终执行结果更新到飞书营销文档 `导航目录类提交` 章节
- 飞书营销文档、过程记录文档与当前进度记录是否一致

## 13. 推荐执行节奏

为了避免漏项，建议按以下节奏执行：

1. 先做清单统计
2. 每次只以前方一个站点作为当前执行单位
3. 单站完成后立即更新过程记录
4. 单站完成后同步核对“已处理数 / 剩余数 / 当前断点”
5. 连续执行时间较长时，主动回看任务说明、执行进度和飞书材料
6. 最后一轮做全量回扫

## 14. 附：执行时的重点提醒

### 14.1 最容易出错的地方

- 把目录中的一段连续站点误认为“整个目录”
- 把 `待审核` 误认为“已经完成”
- 提交后没有拿到复查链接
- 邮件验证没有继续做完
- 站点已经坏了，但没有明确记录原因

### 14.2 本轮必须坚持的底线

- 本轮按“目录级清空”定义完成，而不是按“连续片段处理完成”定义完成
- `导航目录类提交` 目录必须全部覆盖
- 每个目标必须有结论
- 每个结论必须有依据
- 每个已提交目标必须能复查

这四条不满足，本轮就不算完成。
